# **Chapter 1 — Grid and Hypercube: Core Data Structures**

## **1.1 The Grid — Root Runtime Container**

A Grid is the root runtime container for one complete Hypergrid deployment. It owns all Hypercubes, the Hypergraph, the EventLog, the CrdtLog, the NamespaceRegistry, all Spaces, all federation peer relationships, and the plugin registry. Each domain operating system (Kogi, Ume, Qala) is a Grid deployment. Multiple Grids can federate via CrossGridLink edges. Within a single Grid, all data shares one Universal Cell Store, one EventLog, and one Hypergraph.

## **1.5 Storage Encoding Strategies**

Hypercubes choose their storage encoding at creation time based on expected data density. The encoding determines physical storage layout and index strategy in the CellStoreBackend. All encodings produce identical logical query results — the difference is performance and storage cost.

| Encoding | When To Use | Physical Schema | Lookup Perf | Storage Cost |
| :---- | :---- | :---- | :---- | :---- |
| Dense | N=2 with small, fully-populated key sets. Every row×column pair has a value. All conventional 2D entity×field cubes. | PostgreSQL 2D row-per-entity layout. attr\_map stored as JSONB column. O(D₁.card × D₂.card) rows. | O(1) primary key. Range scans contiguous. SIMD-friendly aggregations. | O(D₁.card × D₂.card)  — predictable fixed cost |
| Sparse | Any axis with cardinality \> 100K. TimeAxis, GeoAxis, GraphAxis. Most coordinate combos have no value. | Key-value table: (k₁, k₂, ..., kₙ) → attr\_map in a hash-indexed table. Only non-null cells stored. | O(log n) via composite BTree/BRIN index on dim key columns. | O(non-null cells) — scales with data, not with key space |
| Hybrid | D₁×D₂ dense (entity × property field); D₃–Dₙ sparse (time, region, tenant). Most common production pattern. | Dense 2D base table for D₁×D₂. Separate sparse key-value extension table for D₃–Dₙ cells. Two physical tables joined at query time. | O(1) for base 2D queries. O(log n) for higher-dim extension queries. | Dense base cost \+ sparse extension. Best of both worlds. |

| Implementation Note: Use Hybrid for ALL domain entity cubes (kogi.portfolio.components, ume.kernel.modules, qala.solutions). The entity×field D₁×D₂ slice is dense and hot-path. Time, category, and tenant dimensions are sparse. Using Dense encoding for a TimeAxis would pre-allocate billions of empty cells. |
| :---- |

## **1.6 Schema Evolution — Live Zero-Downtime Modifications**

Hypercubes evolve without downtime. Additive schema changes are CRDT-commutative — all federation peers safely apply them independently and converge. Destructive changes require a governance gate.

| Operation | Safety Class | Protocol | Federation-Safe? | Downtime? |
| :---- | :---- | :---- | :---- | :---- |
| Add new DimensionAxis (Dₙ₊₁) | Safe — additive | Register axis in cube schema. Existing cells gain new dim with null/default key. New cells use new dim immediately. | Yes — additive SchemaEvent commutes | None |
| Add new AttributeKeyDef | Safe — additive | Register new key in AttributeKeyRegistry. Existing cells return default\_value for new key. No migration. | Yes — commutes | None |
| Expand enum variant set | Safe — additive | Add variant to EnumDef. Existing values remain valid. New variant available immediately. | Yes — commutes | None |
| Rename attribute key | Safe with alias | Add alias from old key to new key. Old key remains readable; writes go to new key. Remove alias post-migration. | Yes — alias commutes | None |
| Change CRDT semantics | Risky — careful | Schema version bump. Existing values unchanged. New semantics apply only to mutations after schema version change. No retroactive merge. | Caution: inflight concurrent ops may misbehave during version transition | None |
| Remove attribute key | Destructive — governance gate | Requires GovernanceProposal vote. Key tombstoned (not deleted from EventLog). Historical values preserved for AS\_OF queries. | Yes — after vote applied | None (post-approval) |
| Remove DimensionAxis | Destructive — governance gate | GovernanceProposal vote required. All cells on removed axis tombstoned. EventLog preserves full history. | Yes — after vote applied | Brief recommended |
| Change axis KeyType | Breaking — migration required | Add new axis; old axis migrated via background job. Dual-write window. Requires FeatureFlagController. | No — requires coordinated migration | Migration window |

# **Chapter 2 — HG-CRDT: Distributed Consistency Engine**

## **2.1 Three-Level CRDT Architecture**

HG-CRDT operates at three distinct granularity levels simultaneously. Every implementor must understand all three levels to build correct federation, multi-user editing, and schema evolution.

| Level | Scope | Operation Class | Merge Strategy | Storage Location |
| :---- | :---- | :---- | :---- | :---- |
| Grid-level | Full Grid sync across federation peers | Gossip: each peer maintains VectorClock per grid; delta sync on 30s heartbeat | VectorClock element-wise max; delta replay in causal order | CrdtLog table (PostgreSQL) \+ Redis hot buffer |
| Hypercube-level | Schema: dimension additions, attribute registrations | SchemaEvent log: ordered, idempotent. Non-conflicting if additive. | All additive changes commute. Destructive changes blocked by governance gate. | SchemaEventLog table (PostgreSQL append-only) |
| Cell-attribute-level | Individual TypedAttrValue mutations | Per-attribute CRDT semantics. Each AttributeKeyDef has independent CrdtSemantics. | LWW | OR-Set | Counter | Lattice | AppendLog | JSON-deep | Custom | CellStore (PostgreSQL) \+ CrdtLog delta |

## **2.2 CrdtOperation — The Fundamental Mutation Unit**

Every state change in Hypergrid is expressed as a CrdtOperation. This is the unit of federation delta sync, the unit of the CrdtLog, and the unit of conflict detection. All writes — users, AI engines, federation sync, schema migrations — produce CrdtOperations.

## **2.3 Merge Engine — apply\_crdt\_op()**

The merge engine is the heart of HG-CRDT. It applies incoming CrdtOperations from any source (local user, federation peer, AI writeback, migration) in a way that preserves all CRDT invariants. The function is deterministic: the same set of operations applied in any order always produces the same result.

| impl CrdtMergeEngine {     pub fn apply\_crdt\_op(         \&self,         op: \&CrdtOperation,         store: \&mut dyn CellStoreBackend,         event\_log: \&mut EventLog,     ) \-\> Result\<MergeResult, CrdtError\> {         match op {             CrdtOperation::SetAttr { coord, attr\_key, value, timestamp, actor } \=\> {                 let crdt \= self.registry.crdt\_semantics\_for(coord.cube\_id, attr\_key)?;                 match crdt {                     // ── LastWriteWins ─────────────────────────────────────                     CrdtSemantics::LastWriteWins \=\> {                         let current\_ts \= store.get\_cell(coord.grid\_id, coord)                             .and\_then(|c| c.attributes.get(attr\_key))                             .and\_then(|a| a.vector\_clock());                         if timestamp.dominates(\&current\_ts.unwrap\_or\_default()) {                             store.put\_attr(coord, attr\_key, value.clone())?;                             event\_log.append(EventEntry::set\_attr(op))?;                             Ok(MergeResult::Applied)                         } else {                             // Losing write: record for conflict surfacing                             event\_log.append(EventEntry::conflict(op, ConflictKind::LwwLosing))?;                             Ok(MergeResult::ConflictRecorded { kept: "current".into() })                         }                     }                     // ── Status Lattice ────────────────────────────────────                     CrdtSemantics::Lattice(lattice\_def) \=\> {                         let current\_state \= store.get\_attr\_string(coord, attr\_key)                             .unwrap\_or\_default();                         let new\_state \= value.as\_str().unwrap\_or\_default();                         let merged \= lattice\_def.join(\&current\_state, new\_state);                         // Lattice join \= least upper bound: always advances state, never regresses                         if merged \!= current\_state {                             store.put\_attr(coord, attr\_key, TypedAttrValue::Text(merged))?;                             event\_log.append(EventEntry::set\_attr(op))?;                         }                         Ok(MergeResult::Applied)                     }                     \_ \=\> self.apply\_generic(crdt, op, store, event\_log),                 }             }               CrdtOperation::AddToSet { coord, attr\_key, element, unique\_tag, .. } \=\> {                 // OR-Set: always add the element with its unique\_tag.                 // Concurrent adds to same logical value with different tags: BOTH survive.                 store.or\_set\_add(coord, attr\_key, element.clone(), \*unique\_tag)?;                 event\_log.append(EventEntry::or\_set\_add(op))?;                 Ok(MergeResult::Applied)             }               CrdtOperation::RemoveFromSet { coord, attr\_key, unique\_tag, .. } \=\> {                 // OR-Set: remove ONLY the entry with this exact unique\_tag.                 // Concurrent adds of the same logical value with different tags survive.                 store.or\_set\_remove(coord, attr\_key, \*unique\_tag)?;                 event\_log.append(EventEntry::or\_set\_remove(op))?;                 Ok(MergeResult::Applied)             }               CrdtOperation::IncrCounter { coord, attr\_key, delta, node\_id } \=\> {                 // GrowOnly counter: delta must be \> 0\. PN-Counter: any sign.                 let crdt \= self.registry.crdt\_semantics\_for(coord.cube\_id, attr\_key)?;                 match crdt {                     CrdtSemantics::GrowOnlyCounter \=\> {                         if \*delta \<= 0 { return Err(CrdtError::GrowOnlyViolation); }                         store.counter\_incr(coord, attr\_key, \*delta, \*node\_id)?;                     }                     CrdtSemantics::PNCounter \=\> {                         store.counter\_incr(coord, attr\_key, \*delta, \*node\_id)?;                     }                     \_ \=\> return Err(CrdtError::WrongCrdtType),                 }                 event\_log.append(EventEntry::counter\_incr(op))?;                 Ok(MergeResult::Applied)             }               CrdtOperation::TransitionState { coord, attr\_key, from\_state, to\_state, .. } \=\> {                 // Lattice: verify transition is valid in partial order.                 let crdt \= self.registry.crdt\_semantics\_for(coord.cube\_id, attr\_key)?;                 if let CrdtSemantics::Lattice(lattice) \= crdt {                     if \!lattice.is\_valid\_transition(from\_state, to\_state) {                         return Err(CrdtError::InvalidStateTransition {                             from: from\_state.clone(), to: to\_state.clone()                         });                     }                     let current \= store.get\_attr\_string(coord, attr\_key).unwrap\_or\_default();                     let merged \= lattice.join(\&current, to\_state);                     if merged \!= current {                         store.put\_attr(coord, attr\_key, TypedAttrValue::Text(merged))?;                         event\_log.append(EventEntry::state\_transition(op))?;                     }                     Ok(MergeResult::Applied)                 } else {                     Err(CrdtError::WrongCrdtType)                 }             }               \_ \=\> self.dispatch\_specialized(op, store, event\_log),         }     } } |

## **2.4 VectorClock — Causal Ordering**

The VectorClock is a HashMap\<NodeId, u64\>. Every CrdtOperation carries the issuing node's VectorClock. Receivers use it to determine whether operations are causally ordered, concurrent, or duplicated. NodeIds are formatted as "{federation\_node\_id}:{identity\_tag}" to carry identity context alongside causal context.

| pub struct VectorClock(pub HashMap\<NodeId, u64\>);   impl VectorClock {     // Advance this node's logical clock before any local mutation     pub fn tick(\&mut self, node\_id: NodeId) \-\> u64 {         let counter \= self.0.entry(node\_id).or\_insert(0);         \*counter \+= 1;         \*counter     }       // Merge two clocks: element-wise maximum (call on receiving remote ops)     pub fn merge(\&mut self, other: \&VectorClock) {         for (node, \&ts) in \&other.0 {             self.0.entry(\*node)                 .and\_modify(|v| \*v \= (\*v).max(ts))                 .or\_insert(ts);         }     }       // Does self causally dominate other? (self happened-after or equal)     pub fn dominates(\&self, other: \&VectorClock) \-\> bool {         other.0.iter().all(|(node, \&ts)| self.0.get(node).copied().unwrap\_or(0) \>= ts)     }       // Are these clocks concurrent? (neither happened-before the other)     pub fn concurrent\_with(\&self, other: \&VectorClock) \-\> bool {         \!self.dominates(other) && \!other.dominates(self)     }       // happened\_before: self causally precedes other     pub fn happened\_before(\&self, other: \&VectorClock) \-\> bool {         self.0.iter().all(|(n, \&ts)| other.0.get(n).copied().unwrap\_or(0) \>= ts)         && self.0 \!= other.0     }       // Delta: which (node, ts) pairs in self are newer than other?     // Used to compute what to send in federation delta sync     pub fn delta\_since(\&self, other: \&VectorClock) \-\> HashMap\<NodeId, u64\> {         self.0.iter()             .filter(|(node, \&ts)| ts \> other.0.get(node).copied().unwrap\_or(0))             .map(|(\&node, \&ts)| (node, ts))             .collect()     } }   // NodeId format for identity-aware CRDT: // "{federation\_node\_id}:{identity\_tag}" // Example: "node-us-east-1:@jordan-dev" // This ensures identity-tagged ops carry the correct causal context // and enables per-identity conflict tracking |

| :---- | :---- | :---- | :---- |
| LastWriteWins (LWW) | Highest VectorClock timestamp wins. Tiebreak: ActorId lexicographic sort. | Losing write stored in ConflictRecord; surfaced to actor via notification. Oba logs conflict. | name, description, title, config, JSON blobs, enum fields, reference IDs, all human-authored fields |

## **2.6 Federation Sync Protocol — Complete 8-Phase Sequence**

The federation protocol is the complete mechanism for bringing two Grid nodes to mutual consistency. Implementors must handle all 8 phases correctly. Partial implementations will produce data loss or divergence under network partitions.

| Phase | Direction | Exchange | Success Condition | Failure Mode |
| :---- | :---- | :---- | :---- | :---- |
| 1\. Discovery | Either peer initiates | POST /federation/peers { peer\_url, grid\_id, trust\_level }. Mutual HMAC-SHA256 or mTLS challenge-response. Grid IDs exchanged. | Both peers have each other in federation\_peers. VectorClock slot allocated. | Auth failure → reject. Retry with exponential backoff (1s, 2s, 4s…). Alert admin after 5 failures. |
| 2\. Handshake | Both peers | Exchange VectorClock state \+ schema\_hash\_by\_cube \+ last\_event\_sequence. Compute what needs to sync. | Both peers know current VectorClock and schema versions for all shared cubes. | Exchange failure → retry after 5s. Log and alert after 3 retries. |
| 3\. Schema Sync | Both (if schema\_hash differs) | GET /federation/schema/delta?since=schema\_ts. Receive SchemaEvents missing from this peer. Apply AddDimension, RegisterAttrKey ops idempotently. | All schema versions aligned. Same AttributeKeyRegistry contents at both peers. | Schema conflict: additive always accepted. Breaking changes blocked; admin alert required. |
| 4\. Cell Delta Sync | Both peers | delta\_since(peer\_vc) computes op set. Batch in 10K-op chunks. Compress (Zstd level 3). POST /federation/crdt/sync. Receive per-batch ack. | Peer VectorClock advances to cover all local operations. apply\_crdt\_op() applied for all received ops. | Batch failure → resend. Maintain causal in-order delivery per peer chain. Max 3 retries per batch before alert. |
| 5\. Conflict Surface | Receiver → origin | ConflictRecords generated by apply\_crdt\_op() sent back to origin: POST /federation/conflicts { records } | Origin has all ConflictRecords. Routes to affected actors via notification service. | Best-effort delivery. Conflicts also surfaced locally on next read of affected cell. |
| 6\. Namespace Sync | Initiating peer | Exchange NamespaceRegistry entries for entities reachable via CrossGridLink (only entries with federate=true). | All cross-linked entities resolvable at both peers. | At-least-once delivery. Registry ops idempotent; duplicate entries safe to ignore. |
| 7\. Heartbeat | Both peers | Every 30s: GET /federation/heartbeat → { node\_id, vector\_clock, health\_status }. Trigger full delta sync if VectorClock diverged since last heartbeat. | VectorClock stays ≤ 30s behind at steady state. | 3 missed heartbeats → peer marked Degraded. Shadow cell sync suspended. Alert dispatched. |
| 8\. Shadow Sync | Event-driven (ongoing) | Kafka topic: shadow\_sync.{source\_grid\_id}. Producer: source grid on every MirrorAttribute change. Consumer: all subscribing host grids. | Shadow cells updated \< 1s after source mutation at steady state. | Consumer lag \> 5s → alert. Lag \> 60s → shadow cells marked shadow\_status=Degraded. Backpressure applied. |

## **4.4 DimFold and DimExpand — Physical Implementation**

DimFold and DimExpand are the N-dimensional generalizations of GROUP BY and PIVOT. They are the backbone of Hypergrid's analytical capabilities — every dashboard, report, and KPI visualization in Kogi, Ume, and Qala uses one or both.

## **6.8 CrossIdentityMerge Protocol**

| Step | Operation | Data Effect | Reversible? |
| :---- | :---- | :---- | :---- |
| 1\. Pre-flight Check | Validate both source and target partitions belong to the same SovereignEntity. Check for identity\_tag conflicts. | No data change | N/A |

## **12.5 Startup Bootstrap Sequence**

Every Grid node follows a strict startup sequence that ensures the cell store, plugin registry, domain schemas, and federation connections are all fully initialized before accepting any requests. The sequence is idempotent — partial failures can be retried from any step.

| Step | Service | Operation | Blocking? | Failure Handling |
| :---- | :---- | :---- | :---- | :---- |
| 1\. Config load | All | Load and validate all environment variables and config files. Crash-fail on missing required config. | Yes | Fatal: refuse to start. Log all missing config keys. |
| 2\. Storage connectivity | All | Verify PostgreSQL, Redis, and Kafka connectivity. Apply pending database migrations (Flyway/Liquibase). | Yes | Retry with exponential backoff. Alert after 60s. Fatal after 5min. |
| 3\. Plugin registry init | crdt-service | Load and health-check all HypercubePlugin implementations. Call on\_load() for each. Log any Unhealthy plugins. | Yes | Degraded plugins: skip and log warning. Missing required plugins: fatal. |
| 4\. Grid bootstrap | spreadsheet-service | Call DomainStore::bootstrap() for all registered domain systems. Register Hypercubes and AttributeKeyDefs. | Yes | Idempotent: re-registering existing cube/attr is a no-op. Conflicts fatal. |
| 5\. EventLog recovery | crdt-service | Scan unapplied CrdtLog entries (applied=false). Re-apply in causal order. Advance VectorClock to current state. | Yes | On conflict: apply CRDT merge as normal. Log recovery events. |
| 6\. Namespace warm-up | namespace-service | Pre-populate Redis namespace resolution cache for all entries with last\_resolved\_at in last 7 days. | No (async) | Failure: cache starts cold. Resolution still works via PostgreSQL fallback. |
| 7\. Federation handshake | federation-coordinator | Initiate handshake with all registered federation peers. Run schema sync and delta sync for any diverged VectorClocks. | No (async) | Failure: node operates standalone. Federation retried every 30s. |
| 8\. AI engine warm-up | writeback-service | Health-check all AIEngineAdapter plugins. Pre-load model context for high-priority compute models. | No (async) | Failure: AI compute degrades gracefully. Cache serves stale values. |
| 9\. Ready signal | All | Set readiness probe \= healthy. api-gateway begins routing traffic to this node. | N/A | Only reached if steps 1–5 all succeeded. |
