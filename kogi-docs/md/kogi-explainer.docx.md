## **What is Kogi?**

Kogi is a platform — a place on your phone or computer — where you can manage everything about your work life in one spot. Think of it as a control center for people who work for themselves, run small businesses, or belong to worker-owned organizations.

|  | THINK OF IT THIS WAY: Kogi is like a Swiss Army knife for work — but with AI inside. Instead of carrying a separate knife, screwdriver, scissors, and bottle opener, Kogi combines your work planner, bank account, invoice system, team communication, and business tools in one place — and they all know what each other is doing. |
| :---- | :---- |

## **What Can You Do With Kogi?**

* Organize and track your projects and tasks (like a to-do list that actually thinks)

* Send invoices and get paid — automatically connected to your project work

* Manage your money in specialized accounts for savings, taxes, benefits, and emergencies

* Find skilled people to help with projects — and pay them securely through the platform

* Run a democratic organization — make group decisions, vote on proposals, manage shared money

* Get an AI assistant that watches everything and tells you what needs attention today

## **The Big Idea**

Most working people use lots of different apps — one for tasks, one for money, one for communication, one for finding help. The problem is those apps don't talk to each other. You spend hours copying information between them and things fall through the cracks.

Kogi connects all of these things. When you finish a project, it helps create the invoice automatically. When you get paid, it puts the right amount in your tax savings account. When you need help, it finds qualified people from its marketplace. Everything is connected, so you spend less time managing tools and more time doing actual work.

## **Why Cooperatives Need Different Tools**

Running a worker-owned organization is fundamentally different from running a traditional business. Decisions are made democratically. Profits are shared. Members have rights and responsibilities. Finance is transparent to everyone. And every major change needs a vote.

Most business software ignores all of this. It assumes a hierarchy — an owner at the top, employees below. Kogi is built for the other way: a group of equals, working together, with tools that match how cooperatives actually function.

## **Governance: Democracy in Software**

Kogi's governance tools make democratic decision-making fast, transparent, and accountable. Any member can propose a change. All members vote. Decisions are recorded permanently. Funds are released automatically when votes pass.

| Proposal System Any member can write and submit a proposal — a budget request, a new policy, a hire decision, a project direction. The AI can help draft proposals based on platform data. *Example: A cooperative votes on whether to accept a $25,000 project. The proposal includes the project scope, expected workload per member, and projected earnings per person — all auto-populated by Kogi.* |
| :---- |

| Transparent Treasury Every financial movement — incoming payments, payroll runs, expense approvals — is visible to all members with the permissions to see it. No surprises, no hidden fees, no trust-me accounting. *Example: Before the monthly payroll run, every member can see exactly how much revenue came in, what expenses are being deducted, and what each person will receive — before it happens.* |
| :---- |

| Cooperative Payroll Kogi can distribute earnings to all members according to your cooperative's rules — equal split, hours-weighted, contribution-based, or any formula you define. It handles the calculation, the transfer, and the records. *Example: A 7-person cooperative pays out monthly. Each person logged different hours. Kogi calculates each person's share based on the hours-weighted formula the group voted on last quarter, then executes all 7 transfers.* |

## **System Architecture Overview**

Kogi is a distributed platform built on a polyglot microservices architecture. The system is organized in layers: a kernel/host layer for bare-metal performance, a services layer for domain logic, a platform intelligence layer for analytics and AI, and client layers for web, mobile, and desktop.

| Layer | Technology | Responsibility |
| :---- | :---- | :---- |
| Kernel & Host | Zig (kernel), Rust (host/server/modules) | OS-level operations, memory management, host node coordination, IPC |
| Platform Services | Go microservices | Domain logic: auth, portfolio, exchange, bank, office, community, marketplace |
| Intelligence Engine | Scala 3 (kogi-engine, JVM) | Analytics, recommendations, matching, risk, graph traversal, AI workflows |
| Build System | Bazel | Hermetic, incremental builds across polyglot monorepo |
| Web Client | Angular (TypeScript) | Primary browser-based UI; SPA with module-based routing |
| Mobile Clients | Kotlin (Android), Swift (iOS) | Native mobile apps; real-time sync with platform services |
| Desktop Client | Java | Cross-platform desktop; full feature parity with web |
| Data Layer | PostgreSQL \+ Apache Kafka \+ Redis | Persistent storage \+ event streaming \+ caching |

kogi-engine is the central analytics and intelligence platform. Written in Scala 3, it exposes a unified KogiEngine facade that composes 15+ specialized sub-engines. All platform event streams flow through kogi-engine for processing, enrichment, and action generation.

| :---- | :---- |

## **Distributed Node Architecture**

Kogi is designed for distributed deployment. Each deployment node runs the full platform stack. Nodes coordinate through a consensus mechanism (Raft/Bully leader election) embedded in ShangoOS. The kogi-engine can be federated across nodes using Kafka event bus for stream sharing and CRDT-based merge strategies for distributed state convergence.

* Leader election: Raft consensus for coordination; Bully algorithm as fallback

* Event streaming: Apache Kafka for inter-node event distribution

* State sync: CRDT-based merge for recommendation profiles and graph state

* Caching: Redis for user profiles, session state, and hot data paths

## **Portfolio Data Model**

The portfolio system is the foundational data model of the platform. All work, resources, and artifacts are organized within a hierarchical container taxonomy:

| Component Type | Category | Description |
| :---- | :---- | :---- |
| Portfolio | Item | Top-level container for an entire work portfolio |
| Program | Item | Collection of related projects with shared strategic objective |
| Project | Item | A bounded work unit with defined scope and deliverables |
| Resource | Item | A tracked asset, person, or capability within a project |
| Artifact | Item | A deliverable, document, or output from a project |
| Binder / Book / Record | Container | Organizational containers for grouping components |
| Registry / Archive | Container | System-level containers for classification and historical storage |

## **Key Design Principles**

* Single data graph: all modules share one underlying data model — no data duplication, no sync lag

* Event-driven: all state changes propagate as events through kogi-engine for consistent materialization

* Approval-first AI: agents suggest and prepare; users confirm before consequential actions execute

* Immutable audit trail: all financial operations and governance actions logged with full provenance

* Modular deployment: each module can be deployed independently; value compounds as more are activated
