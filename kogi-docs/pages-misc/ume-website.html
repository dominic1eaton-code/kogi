Core Concepts

The OrgOS model

Six interlocking systems that together form a living, governable, scalable Organisation Operating System.

OrgKernel
The Core

The running instance of the UME kernel for a specific organisation. Composition root, resource manager, and supervisor for all OrgApps. Mediates every data access and every cross-domain event — no module can bypass it.

OrgApps
42 Domain Modules

Finance, HR, Legal, Compliance, Risk, Sales, Ops, and 35 more. Each OrgApp implements a specific organisational capability and contributes its state to the SDO digital twin. Previously called organisation modules — now with ODD and OrgDNA integration.

ODD — OrgDeviceDriver
Actor Governance

A formal contract for every actor in the org — human employees, AI agents, IoT devices, and third-party platforms. Defines capabilities, constraints, data access rights, rate limits, escalation triggers, and audit requirements. Validated in <5ms per action.

SDO
Digital Twin

Software Defined Organisation — the complete runtime representation of your organisation. All OrgApps, all OrgExecs, all OrgCPUs, all data flows, all organisational state. Updated within 500ms of any event. Queryable. Simulatable.

OrgDNA
Config as DNA

The exportable, versionable master configuration package of a fully configured OrgOS. Captures kernel config, all OrgApps, ODD templates, RBAC policies, chart of accounts, KPIs, and jurisdiction compliance packs. Clone it. Fork it. Franchise it.

DAO / DLT
Multi-Org Network

Connect independent OrgOS instances into a DAO with shared smart contract governance and a distributed ledger. Cross-org OrgMemory is immutable, cryptographically verified, and replicated across all member nodes. Inter-org transactions confirm in <5 seconds.

Actor Model

Every actor. One governance model.

ODD contracts apply uniformly to all actor types — no exemptions for AI, no loopholes for devices.

Human OrgExec

Natural persons — employees and contractors. Governed by ODD contracts that define exactly which OrgApps they can access, what actions they can take, and what requires escalation. Same enforcement as AI agents.

AI Agent OrgExec

LLM-powered or rule-based autonomous agents. Subject to identical ODD enforcement as human OrgExecs — no AI exemptions. Rate limits, capability grants, and escalation triggers apply without exception.

OrgCPU

Machines, IoT devices, sensors, manufacturing equipment, POS terminals, and any non-human device. Governed by ODD device driver contracts. Support data reporting at up to 10,000 messages per second per OrgOS.
